模型连接配置

API Key 仅发送到此电脑的本地服务，保存在后端内存。重启服务后需要重新输入；也可以在项目的 .env 文件配置。

密钥不会回显，也不会写入浏览器存储或审计记录。默认模型为 deepseek-flash；请填写账户实际可用且支持工具调用的模型名称。

保存配置只检查输入格式；首次执行才会验证鉴权、余额和工具调用能力。模型请求会消耗 DeepSeek API 额度。

这个 Demo 实际运行什么

真实部分
DeepSeek 根据订单事实与工具回执，自主选择下一项工具并生成参数。每轮模型调用、工具参数、执行结果和人工决定都可以查看、导出。
模拟部分
OMS、库存、调拨、物流、客服和管理者角色均为业务模拟。物流工具按次推进模拟时间，不是真实运输；不会修改真实订单或发送外部通知。
后端约束
工具白名单、参数校验、承诺版本、幂等去重、费用阈值、人工审批与履约关闭条件由程序独立执行，模型不能覆盖。
运行边界
单订单、单智能体、内存会话；不包含企业登录、持久数据库或生产系统接入。每个场景创建独立沙箱；页面刷新或服务重启后请重新新建演示。最多 22 轮、32 次工具调用和 20 分钟，超限转人工。

场景重点观察
常规缺货调拨500 件订单、120 件缺口，比较 360 元和 480 元方案，按权限执行并跟踪模拟签收。
锁库失败后重选选择昆山邻仓时注入库存争抢，返回失败回执；模型需要刷新事实并改选太仓仓。
超阈值人工审批可行方案为 860 / 980 元，超过 500 元示例阈值。模型必须等待页面中的人工批准。

所有数字均为演示设定，不是实际企业政策。模型可能选择不同方案或升级人工，页面不会把它改写成固定成功轨迹。
